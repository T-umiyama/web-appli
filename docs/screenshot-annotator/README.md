# スクショ注釈ツール

`apps/screenshot-annotator/index.html` をダブルクリックで開く、またはホームのカードから起動する。単一HTMLで動作し、画像処理にサーバーや外部サービスを使用しない。

## 元ファイルと移植範囲

ユーザー提供の `screenshot_annotator_single_file_v9_ctrl_c_copy.html` を移植した。最後の指示に従い、見た目はホームに合わせたNeo-Brutalismへ変更した。紙色、黄色・ピンク・紫、太い枠線、硬い影を使用する。初回移植時は元HTMLのscriptブロックを完全に維持した。その後、文字入力を実際の配置位置と一致させるため、入力欄・描画・座標変換を調整した。

CSS・JavaScriptを埋め込んだ単一HTMLのままで、外部ライブラリ・CDN・フォントを追加していない。

## 操作

1. スクリーンショットを `Ctrl+V` / `Command+V` で貼り付ける。「画像ファイルを開く」、画像ファイルのドロップ、クリップボード読込ボタンも利用できる。
2. 四角枠、円・楕円、矢印、直線、ペン、文字、番号、ぼかしで注釈する。選択ツールで移動・ハンドルによるサイズ変更・見た目の編集・Deleteによる削除ができる。
3. 「コピー」または `Ctrl+C` / `Command+C` で編集済み画像をコピーする。「PNG保存」でダウンロードする。

- 文字はEnterで確定、Shift+Enterで改行、Escで取消。IME変換中のEnterは元の動作を維持。
- 文字入力はクリック位置を起点とし、確定後と同じCanvas上にプレビューする。入力欄の背景・枠・影・余白・リサイズハンドルは表示しない。倍率・フォントサイズ・改行を確定時に変えない。
- 入力中の文字は確定前のプレビューで、画像と同様にメモリ上だけで保持する。既存文字の再編集では元の文字を重ねて表示しない。
- Ctrl/Command+Zで戻す、+Yでやり直し、+SでPNG保存。ズーム操作も元のショートカットを維持。
- 「注釈クリア」は元画像を保ち、注釈だけ消す。「画像リセット」は読み込んだ画像の初期状態へ戻す。
- 線の太さ・文字/番号のサイズ・矢印の大きさ・ぼかしの粗さは、数値欄へ直接入力するか、右の▾から候補を選べる。線幅は小数も使える。選択済み注釈にも即時反映する。
- 候補は上下キーで選びEnterで適用、Escで閉じる。空欄や設定範囲外では直前の有効値を保ち、欄から離れたときにその値へ戻る。
- 矢印の先端は「塗りつぶし・線のみ・なし」から選ぶ。太い線・短い矢印・斜めでも線が終点からはみ出さないよう描画する。

## 保存と失敗時の挙動

画像と注釈は画面内のメモリーだけに保持し、自動保存しない。再読込・タブ終了前にコピーまたはPNG保存する。画像を新たに読み込むと注釈は初期化される。ファイル選択の取消や画像以外の貼付では既存画像を置き換えない。

クリップボードAPIの利用可否・権限はブラウザや端末の設定に依存する。直接読込が失敗した場合はCtrl/Command+Vの案内を表示する。画像コピーが失敗した場合は元HTMLどおりPNG保存へ切り替える。ダウンロード先はブラウザの設定に従う。表示倍率を変えてもPNGは元画像の解像度で出力する。

## 初回移植の検証

2026-10-21にPC Google ChromeをPlaywrightから起動し、`file://` で以下を確認した。

- 起動、ホームへの相対リンク、画像なしのコピーエラー。
- 960×600の合成画像をファイル入力から読込。
- 四角・楕円・矢印・直線・ペン・ぼかし・番号・日本語文字の描画。
- Enterによる文字確定、戻す・やり直し、選択・ドラッグ移動、選択注釈の色変更。
- 拡大と100%への復帰、PNGファイルのダウンロード。
- Ctrl/Command+Cによる画像書込API呼出（クリップボードAPIをモック）。
- 注釈クリアで画像を維持、再読込で画像が永続化されないこと。
- 実行中のブラウザエラーなし。元scriptとの完全一致。

証拠は `test-results/screenshot-annotator/` の `review.cjs`、`results.json`、`empty-desktop.png`、`annotated-desktop.png`、`export.png`。画面画像を読み戻し、枠線・影・配色と編集キャンバスの表示を確認した。合成画像のみ使用した。

実OSのクリップボード権限・画像貼付、日本語IMEの実操作は未検証。コピー成功経路はAPIモックによる確認であり、実OSへのコピー成功を示すものではない。元HTML由来の編集履歴の範囲や挙動を拡張していない。

## 文字入力位置の回帰試験

2026-10-21、PC Chrome 155.0.8059.85で13項目合格。50%・100%・125%・133.3%、8px文字、日本語/英字、複数行、長文、背景設定、編集中の倍率変更、再編集を確認した。入力中と確定後の9組の画面比較はすべて変更ピクセル数0。比較時はキャレットと選択ハイライトだけを隠している。

クリックした元画像座標と保存座標の誤差は0.02px未満、入力欄左上と画像上の対応位置は1px以内だった。背景・枠・影・余白・リサイズハンドルなし、Esc取消、Shift+Enter改行、合成IME中のEnter抑止、入力中のPNG保存も確認した。実OSの日本語IMEは未確認。

再利用試験は[tests/browser/screenshot-text.cjs](../../tests/browser/screenshot-text.cjs)。Playwrightを使える環境で、リポジトリのルートから実行する。

```sh
node tests/browser/screenshot-text.cjs
```

Playwrightのモジュール場所は`PLAYWRIGHT_MODULE`、Chromeの実行ファイルは`CHROME_EXECUTABLE`で指定できる。試験用の合成画像だけを使い、証拠は`test-results/text-alignment/`へ出力する。

## 矢印・数値候補の回帰試験

PC Chrome 155.0.8059.85で[tests/browser/screenshot-style.cjs](../../tests/browser/screenshot-style.cjs)の9項目が合格。水平・斜め・逆向き・縦・太線/小先端・短線・破線・点線を含む9ケースで、先端から1pxを超える延長ピクセルは0。点線の丸い端も保持している。

数値4項目の候補/直接入力、既存注釈と入力中の文字への反映、無効値保護、キーボード操作、先端3形状、PNG出力を確認。文字入力の既存13項目も合格した。証拠は`test-results/arrow-style/`。ブラウザ試験の環境指定方法は上の文字入力試験と共通。
