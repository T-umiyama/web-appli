# スクショ注釈ツール

`apps/screenshot-annotator/index.html` をダブルクリックで開く、またはホームのカードから起動する。単一HTMLで動作し、画像処理にサーバーや外部サービスを使用しない。

## 元ファイルと移植範囲

ユーザー提供の `screenshot_annotator_single_file_v9_ctrl_c_copy.html` を移植した。最後の指示に従い、見た目はホームに合わせたNeo-Brutalismへ変更した。紙色、黄色・ピンク・紫、太い枠線、硬い影を使用する。元HTMLのscriptブロックは文字列で完全一致し、描画・編集・入出力の処理は維持した。

変更はCSS、ホームへ戻るリンク、見出し、入力欄と状態表示のアクセシビリティ、保存挙動の説明。CSS・JavaScriptを埋め込んだ単一HTMLのままで、外部ライブラリ・CDN・フォントを追加していない。

## 操作

1. スクリーンショットを `Ctrl+V` / `Command+V` で貼り付ける。「画像ファイルを開く」、画像ファイルのドロップ、クリップボード読込ボタンも利用できる。
2. 四角枠、円・楕円、矢印、直線、ペン、文字、番号、ぼかしで注釈する。選択ツールで移動・ハンドルによるサイズ変更・見た目の編集・Deleteによる削除ができる。
3. 「コピー」または `Ctrl+C` / `Command+C` で編集済み画像をコピーする。「PNG保存」でダウンロードする。

- 文字はEnterで確定、Shift+Enterで改行、Escで取消。IME変換中のEnterは元の動作を維持。
- Ctrl/Command+Zで戻す、+Yでやり直し、+SでPNG保存。ズーム操作も元のショートカットを維持。
- 「注釈クリア」は元画像を保ち、注釈だけ消す。「画像リセット」は読み込んだ画像の初期状態へ戻す。

## 保存と失敗時の挙動

画像と注釈は画面内のメモリーだけに保持し、自動保存しない。再読込・タブ終了前にコピーまたはPNG保存する。画像を新たに読み込むと注釈は初期化される。ファイル選択の取消や画像以外の貼付では既存画像を置き換えない。

クリップボードAPIの利用可否・権限はブラウザや端末の設定に依存する。直接読込が失敗した場合はCtrl/Command+Vの案内を表示する。画像コピーが失敗した場合は元HTMLどおりPNG保存へ切り替える。ダウンロード先はブラウザの設定に従う。表示倍率を変えてもPNGは元画像の解像度で出力する。

## 検証

2026-10-21にPC Google ChromeをPlaywrightから起動し、`file://` で以下を確認した。

- 起動、ホームへの相対リンク、画像なしのコピーエラー。
- 960×600の合成画像をファイル入力から読込。
- 四角・楕円・矢印・直線・ペン・ぼかし・番号・日本語文字の描画。
- Enterによる文字確定、戻す・やり直し、選択・ドラッグ移動、選択注釈の色変更。
- 拡大と100%への復帰、PNGファイルのダウンロード。
- Ctrl/Command+Cによる画像書込API呼出（クリップボードAPIをモック）。
- 注釈クリアで画像を維持、再読込で画像が永続化されないこと。
- 実行中のブラウザエラーなし。元scriptとの完全一致。

証拠は `test-results/screenshot-annotator/` の `review.cjs`、`results.json`、`empty-desktop.png`、`annotated-desktop.png`、`export.png`。画面画像を読み戻し、枠線・影・配色と編集キャンバスの表示を確認した。合成画像のみ使用した。

実OSのクリップボード権限・画像貼付、日本語IMEの実操作は未検証。コピー成功経路はAPIモックによる確認であり、実OSへのコピー成功を示すものではない。元HTML由来の編集履歴の範囲や挙動を拡張していない。
